Scene Preset Editor Plan

Turning 573Renderer's scene presets from compiled tables with a countdown into a fully user-editable, JSON round-trippable timeline: tracks, clips, tweens, and an editor that looks and works like a video editor.

Repository 573Renderer, branch feature/fixes at commit 9675261. Every claim about current code cites path:line so it can be checked. Nothing in this document modifies source; it is the plan.

M8 deleted the files section 2 describes: scene_preset.h, scene_registry.h, scene_presets*.cpp, preset_effective.*, preset_params.*, preset_schema.cpp, preset_convert.* and gui_preset_panel.*. For what the code does today read docs/preset_document.md (schema, catalog, evaluator, host, defaults), docs/gui.md (the editor and the library), docs/preset_golden.md (the frozen legacy reference) and docs/gates.md (the CI gates).

1Summary and goals

A scene preset today is a constexpr Preset::Scene table compiled into the renderer (src/preset/scene_preset.h:197-218), driven by a global countdown, an intro block, a list of phases with param overrides, ramps and emitters, and a fixed set of motion integrators (src/preset/preset_host.cpp:411-439). The user can nudge parameters (the "Parameters" pane) but cannot add a layer, move a phase, draw a new model, or save the result. This plan replaces that with a timeline document: an owning, JSON-serializable tree of tracks and clips that the renderer evaluates deterministically per frame, plus a timeline editor in the GUI where every command the engine can perform is a clip the user places, stretches, and configures.

1.1What changes for the user

  • Every preset becomes editable. The built-in screens (18 today, scene_presets_iidx10.cpp:248-359, scene_presets_iidx11.cpp:657-762) still ship, but they are documents. Duplicate one, change anything, save it as JSON, load it back, share it.
  • The timeline is the whole truth. The bottom dock, which for presets shows an inert "0 / 0" scrubber today (src/gui/gui_timeline.cpp:149-150), becomes a multi-track editor. Where a model appears, when a 2D animation plays, when particles fire, when the camera zooms: all of it is a clip on a track, at a frame, with a length; the selectable options sit on their own track above the clips, and named spans (markers) sit on the ruler.
  • The countdown is gone. "time remain N frames" (src/gui/gui_preset_panel.cpp:97-112) and its speed/fade ramp become ordinary tween clips at the end of the timeline. Scrubbing the playhead is how you see the end-of-timer speed-up.
  • Commands, not knobs. Add a command from a palette: draw a 2D cell, play a 2D animation, scroll it, spawn an emitter, draw a 3D model, tween its transform, move the camera, set a light, override any parameter, change render settings, seed the RNG, shake the models, add a selectable option. Each command has a properties modal exposing every parameter the engine honours.
  • 3D transitions are authored, not implied. Model transforms get tween keys with easing (linear, the game's degree-sine, hold, and standard eases) and a curve editor. Option changes (mode select cube, class course camera) get an explicit transition spec in the document. Today transition_step is a runtime parameter (option[<id>].transition_step, src/preset/preset_schema.cpp:580-589, editable in the Parameters pane and the tweak file) but cannot be authored per preset because Scene::Option has no such field (src/preset/scene_preset.h:40-47); every table gets the effective default 4 (src/preset/preset_effective.h:58).
  • Import, export, validate. A preset library panel lists built-in and user presets, with New, Duplicate, Import JSON, Export JSON, and a validation error list. CLI gains --preset-json so exports and tests run from a document file.

1.2Non-goals

  • Not a general NLE. No audio, no video clips, no multi-camera. Only the commands the engine can already perform (plus the per-frame pushes it is missing, see 5.2) are exposed. New engine features are separate work.
  • Not a "show UI" toggle. The clean-background rule stays: chrome layers are still classified in docs/preset_layers.md and gated in CI. The editor lets a user draw a chrome layer in their own preset if they choose, but the built-in defaults never do.
  • Not a change to how the game's mechanisms are derived. Every default document is converted from the tables the RE work produced and must render identically (golden test, 3.9). The editor does not invent behaviour; the RE notes remain the source for what the defaults contain.
  • Not a change to the AFP backends. gui_timeline.cpp's scrubber for the AFP master clip keeps working for those backends; the editor appears only when a preset document is loaded on the scene3d backend.
  • Not a rewrite of Scene3dHost or Gc2dHost. They remain the two things a frame is pushed into (src/preset/preset_host.cpp:621-631).

1.3Guiding principles

No hardcoding

No preset id, build id, model name, package dir, phase count, blend number or transition step is baked into behaviour. Everything the evaluator needs is in the document. Enum values carry string names in JSON, never bare ints.

JSON round-trip

Load(Save(doc)) == doc for every document, including the defaults. Unknown keys are preserved on load and written back. Numbers are stored as doubles and written by nlohmann's default writer, so parse-serialize-parse is lossless (rules in 3.1, "Files and identity").

Timeline is the single truth

The evaluator is a pure function (document, frame, option choices) -> FrameState plus one explicit, enumerated EvalState (particles, RNG, 3D ticks, spin and kick, transition counter, sprite clocks; 5.2) that is re-simulated on seek. No hidden counters, no side effects at phase boundaries.

Defaults are serializable structs

Built-in presets are C++ functions returning Preset::Document built from owning structs (std::string, std::vector, std::variant). They serialize with the same code as user documents. There is no second format.

Comment-free code, docs single source of truth

Every RE fact, unit, and rationale lands in docs/*.md in the same change (tools/ci/check_no_comments.py). The JSON schema is documented in docs/preset_document.md; the editor in docs/gui.md.

Failing test first

Each milestone starts with a test that fails on the current tree. Evaluator behaviour is asserted on FrameState, never on pixels. Editor behaviour is asserted with the ImGui Test Engine on named items.

2.2Runtime evaluation order per frame

PresetHost::RenderFrame(dt) (preset_host.cpp:621-631) draws first and advances after: back sprites (priority >= split), back emitters, Scene3dHost::RenderFrame, front sprites, front emitters, Gc2dHost::AdvanceSprites(dt), then Advance(). Advance (:411-439) is the state machine the plan replaces. Its order matters because later steps read state written by earlier ones, and two steps read last frame's beat state:

1
g_frame++. An integer counter independent of dt (:413). At 120 fps live the counter runs twice as fast as the sprite and model clocks: g_frame++ once per RenderFrame (preset_host.cpp:413) while the sprite and model clocks advance by dt * 60 (gc_host.cpp:208-214, scene3d_host.cpp:196-201) with live dt = 1 / render_fps (render_loop.cpp:277-281, 351).
2
Phase. AdvancePhase: if PhaseAt(frame) changed, zero all accumulated spins and Rematerialize(true, true), which re-pushes camera, projection, lights, alpha, speed, blend, scale, visibility and re-places sprites (:402-409, 482-507, 760-775).
3
Particles age and die at life (:371-375).
4
Ramps. For every ramp of the current phase, elapsed = frame - PhaseStart(); Linear k = t, Sine k = sin(min(elapsed, frames) * degrees_per_frame deg); the value is written straight into the effective copy, overriding tweaks, and holds at to (:285-303).
5
Sprite scales pushed by draw order index (:455-459), which is how a ramp on sprite[X].scale becomes visible.
6
Emitters spawn per current-phase emitter: PhaseStart, EveryFrame, or Beat (parity + grid) (:311-325); ring reach integer-lerps over frames since phase start (:327-331); scatter and life draw from the shared RNG (:352-362).
7
Jitter draws one RNG value per frame when active (:194-205).
8
Motion. Transition counter drops by transition_step; choice camera lerps; per model: skip unless it moves or is the lead-with-options or jitter is on (:229); lead kick decays; spins accumulate; position = jitter, else orbit, else choice lerp, else base; SetModelTransform(position, rotation + spin) (:217-255).
9
Pulse multiplies every model's scale from last frame's beat state (:207-215).
10
Intro lerps lead speed and projection fov over intro.frames since phase start, and keeps writing after it finishes (:257-273).
11
Beat index = rate * (frame - offset) / span for grids A and B (:158-176).
12
Countdown. Decrement; below ramp_below set lead speed, blend, and optionally alpha from linear slopes (:425-438). Global, phase-independent, and it also defines NaturalFrames (:659).

Options are applied outside the frame loop: SetOption records the from-position and camera, sets the transition counter, and only rematerializes if the choice has params (:712-730). Because CopyOptions never fills ChoiceState::params (preset_effective.cpp:132-137), that check is always false and choice params take effect on the next unrelated rematerialize. RNG: Ran3 seeded from rng_seed at reset (preset_rng.cpp:17-47, preset_host.cpp:509-517); the stream position depends on the interleaving of jitter and scatter draws.

2.6The countdown mechanism, and how it dies

The countdown is the one construct that is not on the frame axis. It is a second clock (g_countdown, preset_host.cpp:78) reset to start_frames at load and restart, decremented once per Advance, and compared with ramp_below to switch the lead model into a linear speed/alpha/blend ramp (:425-438). It is also what NaturalFrames returns when set (:659), so export length and "how long is this screen" come from it, not from the phases. The GUI exposes it as a "time remain" slider (gui_preset_panel.cpp:97-112) that jumps the timer without moving the frame counter, so scrubbing it desynchronises the countdown from the phases.

In the timeline document there is exactly one clock: the frame. The countdown becomes:

  • document.length = countdown.start_frames for every preset that has a countdown, because NaturalFrames already prefers the countdown over the phase timeline whenever it is set (preset_host.cpp:659). Presets without a countdown keep today's rule: last clip start plus its content tail (:643-653), written out as an explicit number by the converter so the document never depends on the rule.
  • A model.tween clip on the lead model. Mind the off-by-one: Advance decrements the countdown BEFORE the strict compare g_countdown >= ramp_below returns (preset_host.cpp:428-431), so at frame start_frames - ramp_below the countdown equals ramp_below, no ramp runs, and the model still has its own anim_speed, alpha and blend_mode from ResetPlayback (:534-536). The first ramped frame is start_frames - ramp_below + 1 with elapsed = 1 (:432-435); the last ramped frame is start_frames - 1, the last frame that exists (export captures length frames, NaturalFrames = start_frames; live playback with the loop toggle off pauses at length - 1; Seek clamps to [0, length - 1], 3.2), where the countdown is 1 and elapsed = ramp_below - 1. The converter therefore emits the clip with start = start_frames - ramp_below + 1 and end = null (open-ended, so its duration is length - start = ramp_below - 1) with two keys that sit on the first and the last existing frame: at 0: anim_speed = speed_base + speed_per_frame, alpha = fade_from - fade_per_frame (only when fade_per_frame > 0, clamped 0..1), blend_mode = ramp_blend_mode (hold); at ramp_below - 2: anim_speed = speed_base + (ramp_below - 1) * speed_per_frame, alpha = fade_from - (ramp_below - 1) * fade_per_frame. Ease linear. Both keys are inside the clip's [0, duration] range (the key-range validation of 5.5 uses length - start as the duration of an open-ended clip); no key sits on frame length, which does not exist, and nothing is "held past the end" (today's clamp at 0, preset_host.cpp:428, only mattered because the old host kept advancing past NaturalFrames). Before the clip the model keeps its own values; the tween starts exactly where today's first ramped frame lands. Clip extents in this section are written as [start, end). The same rule covers game over, where start_frames == ramp_below (scene_presets_iidx10.cpp:348-349) and the ramp starts at frame 1, so the clip is [1, null) with its last key at clip-relative 178 (frame 179, the last frame). The tween is emitted ONLY when ramp_below > 1: with ramp_below 0 the countdown branch never runs (g_countdown >= 0 is always true, preset_host.cpp:429), and with ramp_below 1 the first ramped frame would be start_frames itself, past the last frame; so the ten presets whose countdown is a bare {.start_frames = N} (scene_presets_iidx10.cpp:277, 298, 310, 337; scene_presets_iidx11.cpp:664, 677, 689, 701, 713, 735) get length = start_frames and no tween at all, which is what the small example in 3.8 shows.
  • The slider is replaced by the playhead. Dragging into the last ramp_below frames shows the ramp exactly as the game does, and the frame inspector shows the resolved speed, alpha and blend at that frame.

Worked example, IIDX 10 music select (scene_presets_iidx10.cpp:85-91, 249-259: 1800 frames, ramp below 600, speed 0.25 + 0.0025 per frame, fade from 1 by 0.00066666666 per frame, blend 3): length 1800, tween clip [1201, null) with keys at 0: anim_speed 0.2525, alpha 0.99933333, blend_mode additive; at 598 (frame 1799, the last frame, where today's countdown is 1 and elapsed 599, preset_host.cpp:428-438): anim_speed 1.7475 (0.25 + 599 * 0.0025), alpha 0.600667 (1 - 599 * 0.00066666666). The converter emits this from the table and the golden test checks the pushed speed, alpha and blend at frames 1199, 1200 (the pre-ramp check: speed 0.25, alpha 1, blend opaque), 1201 (0.2525 / 0.99933333 / additive), 1500 (1.0 / 0.8) and 1799 (1.7475 / 0.600667) equal today's values.

3.2Units and the frame/time model

  • The frame is the clock. Integer, starts at 0, draw-then-advance exactly as today (preset_host.cpp:621-631; rationale in docs/export_pipeline.md). Frame f is drawn from the state evaluated for f. The frame axis is [0, length). With the loop toggle off, playback pauses on length - 1 (the last frame export captures) and stays there; with it on, the frame after length - 1 is 0 (a wrap is a Seek(0), re-simulated from the frame 0 checkpoint). Seek clamps its argument to [0, length - 1], so no clip is ever evaluated at or beyond length and an open-ended clip's "to document length" simply means "through the last frame". The M4 Test Engine case plays a document to the end and asserts the transport is paused at length - 1.
  • Seconds are display only. The ruler shows both; every stored time is a frame. Converting a document to another fps is an explicit editor action that rescales clip frames, never implicit.
  • Clip-relative time. Tween key at, emitter reach_frames, sprite offset: all relative to the clip start, so a clip can be moved without editing its contents.
  • Angles are stored in radians for model rotation, spin and camera fov (as today, preset_schema.cpp:225-227), and in degrees for the fields the game itself expresses in degrees (emitter ring angles, sine_deg ease rate). Every field descriptor carries its unit; the form shows a degree readout beside radian fields.
  • 2D coordinates are pixels on the document's render canvas (render.width x render.height). The sprite scale pivot is (x + render.width/2, y + render.height/2): today ScaleAbout scales about (sprite.x + 320, sprite.y + 240) (gc_host.cpp:112-115), so the pivot follows the layer's own x, y (in IIDX 10 music select, kMusicSelectSprites, scene_presets_iidx10.cpp:68-83, the first BG_SKY, the second layer in the list, id sprite[BG_SKY], at x 640, y 120 pivots at (960, 360); the second BG_SKY, id sprite[BG_SKY#2], at x 0, y 120 pivots at (320, 360); neither is the canvas centre, and the schema help at preset_schema.cpp:328 is a simplification). The 320/240 emitter centre default (scene_preset.h:166-167) becomes render.width/2, render.height/2. This rule needs the M2 engine change of 2.5: today the 2D renderer draws a fixed 640x480 canvas stretched to the target (gc_render.cpp:22-23, 226-227) and ScaleAbout adds literal 320/240 (gc_host.cpp:114-115); Gc2dHost::SetCanvas(width, height) from the document's render block replaces both, and the 18 converted defaults keep 640x480 so the golden fixture is unaffected.
  • 3D clip time is ticks at 60 ticks per second (scene3d_host.h:33); anim_speed is ticks per document frame. Each model has its OWN tick. The tick of every model named by any track integrates from frame 0 on EVERY frame, visible or not, because today Scene3dHost::RenderFrame advances model.time for every model regardless of visibility (scene3d_host.cpp:196-201) at the anim_speed PushRebind gave it at load; while a model.draw clip of the target is active the tick advances by that clip's resolved anim_speed per frame, and while NO draw clip is active it advances by the anim_speed of the EARLIEST draw clip on that target's tracks (which reproduces today's load-time base speed: no table overrides a hidden model's speed). It continues across clips (clip_time: "continue" means "the value that integral has reached at the clip start", so the attract models, hidden on 0..502 and 793..902, and the ending models, hidden on 0..71, first appear at frame * 0.75 ticks wrapped as the host wraps them, reset to 0 past max_time, scene3d_host.cpp:199) unless a model.draw clip says clip_time: "restart" or a number, in which case that model's tick is set at the clip start. Today's Scene3dHost::SetTime sets one time for every model (scene3d_host.cpp:248-252); the evaluator needs a per-model Scene3dHost::SetModelTime(name, ticks), listed as an M2 engine gap, and pushes it every frame (5.2, step 5). The M2 test pins the attract core tick at frame 502 to 502 * 0.75 ticks (wrapped against the red scene's max_time from the asset length table of 3.9) against the golden fixture.
  • Sprite time is animation frames; a sprite.animate clip with clock: "restart" starts the sprite's frame at offset at the clip start and advances it by speed frames per document frame; with clock: "continue" the sprite's frame carries on from the previous frame. "Playhead" in this document always means the editor's frame; the per-sprite animation frame is the "sprite clock" or "sprite frame".

Two primaries that must run at the same time (two sprites, two beat grids) go on two tracks. The editor draws overlapping clips in sub-lanes inside the track: the primary lane on top, one 16 px modifier lane per overlapping modifier family below it, so a model track with a draw, a tween and a motion clip is three lanes tall and the header shows the lane names. When two clips write the same value at the same frame (a model.draw alpha and a model.tween alpha), the later one in evaluation order wins: tracks in tracks order, and within a track the primary first (its own keys are evaluated WITH the primary, as part of it), then modifiers in clip order, exactly like today's later-override-wins in Materialize (preset_effective.cpp:356-364). Because track order is evaluation order, a modifier track that sits ABOVE its target's draw track is evaluated first and the primary silently overwrites it; validation therefore warns "modifier track X for target Y is evaluated before the draw track", and both the converter and "Add transition to next clip" (4.2) insert modifier tracks directly BELOW the target's draw track. model.tween keyed transform and material transition on a model (model)

A model.tween clip has no params of its own; it acts on the track's target model and its whole content is keys. It is a modifier: it may overlap a model.draw, and where both write a value the tween wins because it comes later in the track's clip order (overlap rule, 3.3). Tweenable values: position, rotation, scale, alpha, anim_speed, spin_per_frame (the rate the per-model accumulator integrates each frame, spin_per_frame row above; the converter emits it for the two iidx11-mode-select spin ramps), blend_mode (hold). Values not present in a key are not touched (so a tween can move only alpha); a value first named at a later key blends in from the frame's already-resolved value, by the one key rule in 3.3 and "Before, between and after keys" below. Option transitions are NOT tween clips: they are the evaluator blend of the transition row in the options table below (4.6). The editor builds a tween between two poses for the user with "Add transition to next clip" (4.2): it inserts a model.tween whose key 0 is the resolved pose at the previous clip's last frame and key 1 the next clip's params.

Tween semantics (the behaviour being preserved is ApplyRamps, preset_host.cpp:285-303, and ApplyMotion, :239-253):

  • Interpolation is component-wise linear on the raw numbers: Euler radians lerp per axis WITHOUT wrapping or shortest-arc (a rotation key from 0 to 4.712389 rad goes the long way, exactly as ApplyRamps does), vec3 per component, scalars directly. Enum values (blend_mode) only hold.
  • Segment eases. For a segment from key A (at a) to key B (at b) at clip-relative frame t, seg_len = b - a: linear k = (t - a) / seg_len; sine_deg k = sin(min(t - a, seg_len) * rate_deg), and the value REACHED at key B and held afterwards is A + (B - A) * sin(seg_len * rate_deg), which equals B only when seg_len * rate_deg is 90 degrees. RED music select's fly-in (35 frames at 3 deg per frame, scene_presets_iidx11.cpp:93-99) therefore rises past its key at frame 30 (sin 90 = 1) and settles at sin 105 = 0.9659 of the way, which is why kMusicSelectSettled pins z at -0.27555565 (:144-149). The editor's key list shows both the authored value and the reached value for sine segments. hold, ease_in, ease_out, ease_in_out, bezier reach B exactly.
  • Ease formulas, with t = (frame - a) / seg_len clamped to 0..1 and value = A + (B - A) * k: hold k = 0 (B applies from key B on); linear k = t; sine_deg as above (not a function of t); ease_in k = t * t; ease_out k = 1 - (1 - t) * (1 - t); ease_in_out k = 2 * t * t for t < 0.5, else 1 - 2 * (1 - t) * (1 - t) (all quadratic); bezier is CSS cubic-bezier(x1, y1, x2, y2): control points (0,0), (x1,y1), (x2,y2), (1,1) with x1, x2 in 0..1, k = y(s) where s solves x(s) = t by exactly 8 Newton iterations from s = t followed by 8 bisection steps when the Newton result leaves 0..1, all in float, so two machines produce the same bits. Every formula lives in eval_tween.cpp and is unit-tested; the same text goes into docs/preset_document.md in M1.
  • Key JSON per ease kind. rate_deg and cp sit on the key next to ease: { "at": 0, "ease": "linear", "values": { "alpha": 0 } }; { "at": 0, "ease": "sine_deg", "rate_deg": 3.0, "values": { "position": [-0.1, 0, -1.0] } }; { "at": 0, "ease": "ease_in_out", "values": { "fov_y": 1.0 } }; { "at": 0, "ease": "bezier", "cp": [0.42, 0, 0.58, 1], "values": { "scale": [1, 1, 1] } }; { "at": 35, "ease": "hold", "values": { "position": [-0.1, 0, -0.25] } }. ease defaults to linear; rate_deg without sine_deg and cp without bezier are validation errors; the last key's ease is ignored.
  • Before, between and after keys. The same rule as the keys row of 3.3: a value named by key 0 holds key 0's value before key 0. A value FIRST named at a later key k is, on every frame from the clip start up to key k, interpolated with key 0's ease from the value already resolved for that target at that frame (by the tracks and clips evaluated before this tween) to key k's value; nothing is captured at the clip start, so the result is pure per frame and re-simulation-free. A value present in any key holds the value it reached at the LAST key that names it, and stays there to the clip end even if later keys name other values. A key that omits a value another key set does not touch that value. eval_tween_tests.cpp (M2) has a case for a two-key tween whose key 0 omits alpha and key 1 sets it, asserting the frames before key 1 blend from the underlying model.draw alpha.
  • Composition with the draw clip. A tween WRITES the base pose fields of the model (position, rotation, scale, alpha, anim_speed, spin_per_frame, blend): it replaces the model.draw value for that frame, and the accumulated spin (the per-model integral of the resolved spin_per_frame, keyed or not, times the kick multiplier while a kick is live) is added on top of the rotation afterwards, as rotation + spin is today (preset_host.cpp:251-253). Orbit and then jitter apply to the position in that order (:243-249): orbit replaces it, and jitter replaces it (mode: "set", the game's mechanism and the default) or offsets it (mode: "add"), see rhythm.jitter below.
  • Camera aspect is hold-only: tweening from or to "auto" is a validation error, and a numeric aspect in a camera.tween key holds.
  • Per-key ease is per key, not per channel. Two channels that need different rates or lengths on the same model go in two tween clips (overlap rule, 3.3).

  • The asset picker (4.4) lists model names from the loaded scene3d dir and cell/animation names from the package, so a clip's model/cell/animation is chosen, not typed. 4.10Playhead synchronisation with the renderer, and export

  • One playhead. The render thread owns the current frame. The GUI reads it from the status snapshot every frame (as gui_timeline.cpp:212-216 reads LiveState) and draws the playhead there. Scrubbing posts PresetCmd::Seek{frame} plus paused; play/pause posts PresetCmd::SetPaused. This replaces the dead AfpCmd::SeekFrame path on the scene3d backend (scene3d_backend.cpp:248-251 ignores every payload today) with a handled command.
  • Seek is deterministic re-simulation. The evaluator is pure per frame except for the explicit stateful set listed in 5.2: particle pool, RNG, per-model 3D tick, per-model spin accumulator and kick multiplier, the option transition counter with its captured from-values, and the sprite clocks. Seek(n) clamps n to [0, length - 1], recomputes all of them from the nearest checkpoint (kept every 256 frames) up to n and pushes the resolved frame, including the new per-model Scene3dHost::SetModelTime(name, ticks) (today's SetTime sets one time for every model, scene3d_host.cpp:248-252; M2 engine gap) and the existing Gc2dHost::SetSpriteFrame per sprite (gc_host.cpp:232-235, addressed by draw-order index; the host maps the track target to that index, M2), so a seek never depends on the previous playhead. For today's largest document (ending, 18 markers, RNG-heavy) this is well under a millisecond per frame of catch-up.
  • Live tick, and one owner of time. While playing, the render loop advances one document frame every 1 / fps seconds of wall time (accumulator), fixing the 120 fps drift noted in 2.2; with the loop toggle off it stops on length - 1, with it on it wraps to 0 (3.2). Render frames that advance no document frame (every second one at 120 fps) re-push the same FrameState. The hosts do NOT integrate time in preset mode: EvalState owns the per-model 3D ticks and the sprite clocks, PresetHost pushes SetModelTime per model and SetSpriteFrame per sprite on EVERY frame as part of the unconditional push (5.2, step 5), calls Scene3dHost::RenderFrame with dt 0 and no longer calls Gc2dHost::AdvanceSprites, so the host tick can never drift from the evaluator's between seeks (today Scene3dHost::RenderFrame(dt) advances model.time by dt * 60 * speed, scene3d_host.cpp:196-201, and Gc2dHost::AdvanceSprites by dt * 60, gc_host.cpp:208-214, which is exactly the drift being removed). The M2 test renders 120 host frames for 60 document frames and asserts the pushed host tick equals the EvalState tick on every frame. During export capture the driver advances exactly one document frame per captured frame, as now (render_loop.cpp:310-319).
  • Export plans length frames (replacing NaturalFrames() in Scene3dCaptureDriver::BeginCapture, scene3d_backend.cpp:39-67) from frame 0 with the current option choices, and the timeline shows the captured range as the existing green tint (gui_timeline.cpp:155-159). An in/out range on the ruler (the export range handles, set by Shift+drag) exports a sub-range: it maps to ExportRequest.max_frames plus a new start_frame. Export fps: the export modal and --preset-export default their fps to document.fps (today RunExport writes the literal 60, preset_test.cpp, and --export-fps defaults to 60); a different export fps is honoured only when it is an integer multiple or divisor of document.fps, in which case the driver advances fps_doc / fps_export document frames per captured frame (or repeats a document frame fps_export / fps_doc times), and any other ratio is refused with a message, so a 60 fps document never plays at half speed in a 30 fps file. The rule goes into docs/export_pipeline.md with a cli_tests case (M3).
  • Edits while playing are allowed: the GUI publishes a new document snapshot and the render thread swaps it at the next frame boundary. ANY document change invalidates EVERY checkpoint: the render thread rebuilds EvalState from frame 0 up to the current frame with the new document (a few thousand frames at well under a millisecond each is a few milliseconds, once per edit), then continues. Comparing "which clips overlap the last checkpoint window" is NOT enough, because an edit before the last checkpoint (moving an emitter, a rhythm.jitter or an rng.seed at frame 10 while the playhead is at 700 with the checkpoint at 512) changes the RNG stream and particle pool the checkpoint holds; a full replay is what makes seek, live state and Restart agree (5.2, 5.3).

5.2The evaluator: document + frame to render commands

Evaluate(frame) is pure with respect to the document, the option choices and the explicit EvalState; nothing else carries state between frames. Order, replacing Advance:

1
Start from document globals: render, camera, lights; every model hidden; no sprites.
2
For each track in order (skipping muted tracks, muted clips, and non-solo tracks when any track is solo): find clips with start <= frame < end (end null = length; event clips match only frame == start) whose when gate matches the current choice; apply the primary first, then the modifiers in clip order. model.draw sets the model visible and its params, then adds the accumulated spin from EvalState (per MODEL; the accumulator holds the sum, over the frames after the winning clip's start up to and including this frame, of the spin_per_frame RESOLVED for each of those frames, draw params then tween keys then choice values, times the kick multiplier live on that frame; it is zeroed in step 4 when a primary with a different start becomes the winner, so a new clip's first frame carries no spin; with a constant rate, no kick and one winner for the whole span it equals spin_per_frame * (frame - start); the old host adds one extra step, the step of the phase's first frame, on EVERY frame of every phase after the first, because AdvancePhase zeroes g_spins and ApplyMotion adds a step in the same Advance, preset_host.cpp:406-407, 239-241, and the golden test tolerates exactly that offset on those frames and nothing on phase 0, 6.3); model.tween and camera.tween sample keys at frame - start and write the base pose (Tween semantics, 3.4); model.motion applies orbit at frame - start, reads the kick multiplier from EvalState, and applies pulse from the beat state OF THE PREVIOUS FRAME (the grids for this frame are advanced in step 4, so PulseScale keeps its one-frame lag, preset_host.cpp:183-192, 421-423); the jitter value drawn in step 4 of the previous Advance is applied to the listed models' positions (mode: "set" replaces the position with {j, j, 0}, the game's mechanism and the default; mode: "add" offsets it, 3.4); sprite commands write sprite instances (keyed by track target) with the sprite clock from EvalState (advanced by speed per frame in step 4, so a tweened speed integrates; with constant speed it equals offset + (frame - start) * speed) resolved through ResolveFrame (gcanim.cpp:182-198) and scroll from sprite.scroll (the scroll offset is fmod(clock * scroll_x, scroll_wrap) on that same per-instance clock, as ScrollOffset is today, gc_host.cpp:45-48, so it persists across clip boundaries with the clock); camera.set, light.set, render.settings, param.override write their values; each write records the winning clip id.
3
Option choice values: for every option, the selected choice's values override the resolved values of the named targets (steady state); if a transition is in flight, the targets named by the old or the new choice are blended from the captured start values to the new choice's values (or, for targets the new choice does not name, back to the clip value resolved in step 2) by the transition's ease and counter (decremented by step per frame, as g_transition, preset_host.cpp:221-222); the kick multiplier of the moved models was re-armed to max(1, transition.spin_kick), negative when the index decreased, when the choice changed (:727-729). An option.select event clip whose start equals this frame performs the same change first, in this step.
4
Stateful step (only on Advance, replayed on Seek), in today's order (preset_host.cpp:413-423): particles age (a particle spawned this step is created at age -1 and is first drawn next frame at age 0, :99, 347, 381, particle rules in 3.4); emitters active this frame spawn according to their spawn rule using the beat state of the previous frame (preserving today's one-frame lag, :317-322); rhythm.jitter draws its ONE RNG value; per model the kick multiplier decays by that model's model.motion.spin_kick_decay toward 1 (or -1, :231-237) and the spin accumulator adds, for the frame about to be drawn, the spin_per_frame RESOLVED for that next frame (the winning draw clip's params, then tween keys, then choice values, the same resolution step 2 will make; a keyed rate is thereby integrated exactly as ApplyRamps plus ApplyMotion integrate a ramped motion.spin_per_frame today, preset_host.cpp:285-303, 239-241) times the multiplier after this decay (per model, one accumulator, so a gate switch between two overlapping primaries only changes the rate); when the model.draw primary that will win NEXT frame has a different start than this frame's winner, that model's accumulator is zeroed instead, and a model.motion clip starting next frame arms its spin_kick; the 3D tick of EVERY model named by any track advances by that model's resolved anim_speed (the earliest draw clip's while no draw clip is active, 3.2) and the sprite clocks by speed; the transition counter drops by step; rhythm.beat advances the beat grids for the next frame; rng.seed event clips whose start is this frame reseed and clear the pool.
5
Push: PresetHost pushes the whole FrameState unconditionally: SetModelTransform, SetModelScale, SetModelAlpha, SetModelSpeed, SetModelBlendByName, SetModelVisibleByName for every model; SetView, SetProjection, SetLights, SetStyle; SetModelTime per model from the EvalState tick; sprite placements (diffed by instance so Gc2dHost keeps the sprite clock by name as today, gc_host.cpp:402-415) and per-sprite SetSpriteFrame from the EvalState clock, scale and scroll; particles drawn from the pool. Scene3dHost::RenderFrame is then called with dt 0 and Gc2dHost::AdvanceSprites is not called: EvalState is the only owner of time (4.10). This closes the gaps where position, rotation, alpha and camera ramps never reached the GPU (preset_host.cpp:229, 487, 500-506).

Determinism and the stateful set. EvalState is exactly: the particle pool; the RNG; per model the 3D tick, the spin accumulator and the kick multiplier; the option transition counter with the captured from-values; the sprite clocks; the beat grid indices and their age; the last jitter draw. A checkpoint is a copy of EvalState taken every 256 frames, and the checkpoint set belongs to ONE document: any ReplaceDocument discards every checkpoint and rebuilds them from frame 0 up to the current frame with the new document (a full replay, a few milliseconds for the longest document), never a partial replay from the last checkpoint, because an edit anywhere in [0, frame] (an emitter, a rhythm.jitter, an rng.seed) changes the RNG stream and the particle pool a later checkpoint holds. Given (document, choices, frame) and the checkpoint at the last multiple of 256 before it, Evaluate yields the same FrameState every time; the golden test relies on this, and so does seek. Seek(n) restores the checkpoint, replays step 4 up to n, and pushes everything, including Scene3dHost::SetModelTime(name, ticks) per model from the recomputed tick (a new per-model setter; today's SetTime writes the same value into every model, scene3d_host.cpp:248-252) and Gc2dHost::SetSpriteFrame per sprite instance from the recomputed clock (the setter exists, gc_host.cpp:232-235). SetModelTime and SetSpriteFrame are pushed on EVERY frame (step 5), not only on seeks, and the hosts integrate nothing in preset mode (RenderFrame(0), no AdvanceSprites), so the host clocks are always the evaluator's; the M2 seek test asserts Seek(n) equals Advance n times for every member of EvalState, per model for the ticks; a second M2 case edits an emitter at frame 10 with the playhead at 700, posts ReplaceDocument, and asserts the resulting EvalState equals a fresh Advance x 700 on the new document.

5.3Threading with the render thread

The plan closes the gap noted in 2.3 for the preset editor: nothing under src/gui/timeline/ and nothing in gui_preset_library.cpp calls PresetHost, Scene3dHost or Gc2dHost. This is a scoped claim: gui_scene3d_panel.cpp, gui_gc2d_panel.cpp and the visibility predicates in panel_registry.cpp (:25, 29) call the hosts directly today and keep that convention until a separate change; the existing tools/ci/check_gui_isolation.py enforces the OPPOSITE direction (ImGui symbols outside src/gui, check_gui_isolation.py:8-14) and cannot prove this one, so M4 adds tools/ci/check_host_isolation.py (fails on PresetHost::, Scene3dHost:: or Gc2dHost:: in src/gui/timeline/ and src/gui/gui_preset_library.cpp) to tools/checks.sh and docs/gates.md. The editor owns an EditorState and posts PresetCmds through App::State::PostCommand (src/state/app_state.h:25-26). The scene3d backend's HandleCommand (src/backend/scene3d_backend.cpp:248-251) starts handling payloads: ReplaceDocument swaps the evaluator's shared_ptr<const Document> at the frame boundary, discards every checkpoint and re-simulates EvalState from frame 0 to the current frame with the new document (the rule in 5.2; no document diffing, because the RNG stream and particle pool make any earlier edit reach every later checkpoint); Seek, SetPaused, SetOption, SetLoop are applied there too. Asset loading triggered by a new document (a new asset id) runs on the render thread under the loading overlay with per-asset progress. Status flows back in the existing snapshot (App::Status / a new PresetStatus struct with frame, playing, length, FrameState summary and validation count), read once per GUI frame. The same snapshot carries the AssetIndex (5.1): after every asset load the render thread publishes, per asset id, its kind, dir, loaded flag, model names, cell names, and animation names with lengths and child parts, so the asset picker, the Add track modal, the hidden-parts checklist, the palette and GUI-side Validate never ask a host for a name; the M2 host test asserts the index is published after ReplaceDocument loads an asset, and the M5 GUI test asserts the picker lists exactly the index's names. This is the same seam the AFP backends already use, so no new mutex is introduced in src/preset.

5.4Undo model

Snapshot undo. EditorState keeps std::vector<Document> past, future; Apply(edit) pushes the current document, applies, clears future, publishes. BeginGesture()/EndGesture() bracket drags and slider edits so intermediate states publish (the viewport follows the drag) but only one undo snapshot is recorded; each intermediate publish is itself a fresh immutable copy posted as PresetCmd::ReplaceDocument, never a mutation of a document the render thread may be reading. Cap 200 entries. Documents are a few KB, so copying is negligible; a diff-based model is not needed and would be a source of bugs. Undo also restores the selection to the clips it applied to when they still exist.

5.5Validation

  • Structural (errors): schema and version; unknown command type; duplicate ids; unknown track kind for a command (param.override, render.settings, rhythm.*, rng.seed and option.select only on scene); duplicate target across tracks of the same kind is allowed only for draw + modifier tracks of one instance, never for two tracks that both hold primaries of the same family (per-target primary rule, 3.3); clip start < 0, end <= start for span clips, and for EVENT clips (option.select, rng.seed) an end that is present and differs from start; key at outside [0, duration]; non-tweenable value in a key; enum value not in the name table; range violations only for hard ranges (bool/enum/int counts), never for soft float ranges (the camera fov_y is soft, 3.4); two primaries of one family overlapping on one TARGET, across all its tracks for model.draw and the sprite family and per track for the rest, unless their when gates are mutually exclusive (3.3); when naming an unknown option or choice, or more than one option; duplicate choice labels within one option; rate_deg without sine_deg or cp without bezier; transition.ease outside hold / linear / ease_in / ease_out / ease_in_out; param.override id or option choice value key not in the schema id grammar; tweening aspect or tweening from or to "auto"; sprite.scroll with no sprite clip of the same track under it; asset id not in assets; markers not sorted or two markers on one frame; a user document whose id equals a built-in id of the same build. Structural (warnings): a model.tween or model.motion clip whose frame range has no model.draw of the same target under any part of it (the model is hidden there, 3.3; camera.tween is exempt); a modifier track that sits above its target's draw track in tracks order ("evaluated before the draw track"); a blend key on a sprite.animate clip (per-node from the package, 3.4).
  • Blocking versus loadable. Only parse errors, a wrong schema string and a higher version prevent a document from loading; every structural error above loads with the problems listed (import modal 4.4, library 4.8) and the evaluator skips the offending clip and evaluates the rest. --preset-json refuses errors unless --force.
  • Asset-dependent (warnings): asset dir missing in the game dir; model, cell or animation name not in the loaded asset; hidden part not in the animation; a drawn 2D layer whose docs/preset_layers.md verdict is chrome or missing (warning for user documents, error for built-ins via CI). The verdicts reach the running app through the build-time generated preset_layer_verdicts.cpp (5.1), so Validate needs no repo path at runtime; CI keeps reading the markdown directly.
  • Runs after every edit (cheap), results shown in the library list, on clip badges and in the status strip count. --preset-json and CI use the same function.

6.2Docs and CI gates: how they keep working

  • check_preset_layers.py stops regex-parsing C++. tools/checks.sh already builds first, so the gate runs 573Renderer.exe --preset-dump-defaults <tmp> (no game data needed), walks every document, collects every sprite.draw/sprite.animate clip's (asset dir, cell or animation) and every hidden_parts entry, and checks docs/preset_layers.md exactly as today (background for drawn, chrome for hidden). It fails loudly if the dump contains zero documents or zero sprite clips, replacing the count self-check (check_preset_layers.py:68-79).
  • check_preset_states.py reads the same dump. "States" become: every markers[].label of every built-in document (the converter carries today's Phase.label as a marker at start_frame, and the tests pin them; a marker is required for every documented state, including spans with no content clip such as the attract "models hidden" spans, docs/preset_states.md:28, 30), and every option choice label. The two-direction check against docs/preset_states.md is unchanged (a documented state with no marker fails, a marker with no row fails); the id prefix rule is dropped in favour of the build field.
  • preset_sweep.py takes documents from the dump and screenshot names and frames from the markers.
  • Banned characters, no comments, file length, gui isolation, machine paths: unchanged and apply to every new file, including docs/preset_document.md and this plan.
  • check_host_isolation.py (new in M4): fails on any PresetHost::, Scene3dHost:: or Gc2dHost:: reference in src/gui/timeline/ or src/gui/gui_preset_library.cpp, the scoped threading claim of 5.3; added to tools/checks.sh next to check_gui_isolation.py and described in docs/gates.md.
