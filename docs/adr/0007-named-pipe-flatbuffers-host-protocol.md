# The preview host protocol is FlatBuffers over a named pipe

The editor and the preview host exchange one length-prefixed FlatBuffers message per request and per reply over a Windows named pipe. The editor side can use Qt's `QLocalSocket`, which is a named pipe on Windows, and the host uses plain Win32 pipe handles and never links Qt. With FlatBuffers both sides share one schema file, messages are read without copying (packages of tens of megabytes travel inline as byte vectors), and vcpkg has a maintained port. Protocol Buffers was rejected because decoding copies the package bytes and the library is heavier to link statically. Cap'n Proto RPC was rejected because its Windows pipe support needs its own event loop in the host, and gRPC because it is the heaviest dependency and opens a TCP port for a link on the same machine.
