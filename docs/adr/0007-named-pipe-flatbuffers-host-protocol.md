# The preview host protocol is FlatBuffers over a named pipe

The editor and the preview host exchange one length-prefixed FlatBuffers message per request and reply over a Windows named pipe. The editor side can use Qt's `QLocalSocket`, which is a named pipe on Windows, while the host uses plain Win32 pipe handles and never links Qt. FlatBuffers gives both sides one schema file, reads messages without copying (packages of tens of megabytes travel inline as byte vectors), and has a maintained vcpkg port. Protocol Buffers was rejected because decoding copies the package bytes and the library is heavier to link statically, Cap'n Proto RPC because its Windows pipe support needs its own event loop in the host, and gRPC because it is the heaviest dependency and opens a TCP port for a same-machine link.
