# afp-core runs in a separate preview host process

The IFS editor never loads afp-core or avs2-core itself. A small preview host executable loads them, receives encoded packages, a frame and a viewport size from the editor, and renders into a D3D9Ex shared texture the editor displays. The editor produces packages the game never shipped, afp-core does not validate its input, and a crash inside it cannot be recovered in-process because its internal state is gone; with a separate host the editor restarts it, keeps the user's work, and reports which edit caused the crash. The host links the afp host library carved out of the renderer and builds with the renderer's static preset, so Qt and the game DLLs never share an address space. A later 32-bit host for older builds needs no change to the editor.
